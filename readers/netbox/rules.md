# Rules of the NetBox reader

Every finding the reader files has a stable dotted rule id, as the core's do (Constitution X),
and callers and tests match on the id, never on the wording. These rules are the reader's own,
never the core's or the Infrahub reader's ([`formats/README.md`](../../formats/README.md),
note 11); the core's are in [`docs/rules.md`](../../docs/rules.md). A finding is the core's
`Finding`, of findings 1's form
([`findings-1.schema.json`](../../formats/findings-1.schema.json)): its severity, as its object
the name in NetBox of what it is about, and a message of one sentence that names the branch
read, or `main`, and never holds a byte of a configuration. A read whose findings hold an error
gives no blueprint ([D-095](../../design/decisions.md#d-095)). The code names each rule by a
module-level constant beginning `RULE`.

A **problem** is a reason the reader document is refused, so that no read is made with it; the
problems' rows come first, their severity `problem` and their object the pointer. The
**findings** follow.

A read judges every rule it can in one pass
([Constitution III](../../design/constitution.md#iii-the-blueprint-is-the-contract)): every
scoped device is rendered, one the mapping refused among them, so that three devices at fault
three ways are three findings in one result. A `read.incomplete` ends the read with what is
filed, since the rest would judge a partial list, and the bracket's close is still taken, so
`read.moved` can stand beside it, or beside `scope.empty`. Each problem of the blueprint built,
which the read holds to blueprint 1 (`blueprint.validate`), is an error under the core's own
rule id ([`docs/rules.md`](../../docs/rules.md), the `blueprint.*` problems), its pointer the
object, and has no row here.

The **command** (`cli.py`; [README.md](README.md), "The command") prints each finding as one line
on stderr, `<severity> <rule> <object>: <message>`, in a result's order, and exits 1 where one is
an error, writing no blueprint; a reader document refused exits 2, a line naming the file and one
for each problem beneath it, `<rule> at <pointer>: <detail>`. It files no rule of its own: what
stops it short of a finding (a variable not set or one the client's rules refuse, a reader
document not read, a `NetBoxError`, `--out` not written) is a line on stderr and exit 2, under no
rule id.

| Rule | Severity | Object | Means, and the remedy |
|---|---|---|---|
| `reader.version.unsupported` | problem | `/reader_version` | The document's `reader_version` is not `1`, and nothing else of it is checked. Write it in version 1's form |
| `reader.invalid` | problem | The member at fault (`/probes`); for a member missing or unknown, the object that lacks or holds it (`""` for the document, `/platforms/0` for a row), the member named in the detail; `""` for a file that is neither JSON nor YAML | The document violates its schema, or the file is no document at all. Correct what the detail names |
| `reader.platform.duplicate` | problem | The later row (`/platforms/1`) | Two rows hold one pair of manufacturer and platform, compared exactly, letter case and spacing included, so the pair would name two packages, or one package twice. Keep one row for the pair |
| `scope.invalid` | error | The scope as given (`site:x`) | The scope is not `tag:<name>` with a name, and nothing is sent to NetBox. Give the scope as `tag:<name>` |
| `netbox.version.unverified` | warning | NetBox's version and the branching plugin's, `<version>/<plugin's>`, `none` where NetBox names no plugin (`4.8.0/1.2.3`, `4.7.5/none`) | The NetBox read is of a pair of versions the reader was not verified on, none of `SUPPORTED` (NetBox 4.7.5 with netbox-branching 1.2.3). Every result of that connection carries it, and it is logged once, at the connect; the read goes on. Verify the reader on that pair, its contract tier against it, before relying on what it reads |
| `branch.unsupported` | error | The branch asked, by its name (`b`) | A branch was asked of a NetBox whose `/api/status/` names no `netbox_branching` among its plugins, so it holds no branch, and nothing is sent. Read `main`, or install the branching plugin |
| `branch.unknown` | error | The branch asked, by its name | NetBox lists no branch of that name, compared exactly, and the read ends before it opens its bracket. Check the branch's name |
| `branch.unready` | error | The branch asked, by its name | The branch's status is not `ready`, given verbatim (`provisioning`, `syncing`, `merged`), and the read ends before it opens its bracket. Read it once it is `ready` |
| `scope.empty` | error | The scope (`tag:fylgja`) | NetBox lists no tag of the scope's name, or no device carries it, so the scope selects no device; `Result.empty` is true. Tag the devices to read, or check the scope |
| `read.incomplete` | error | The list, by NetBox's object type: `dcim.device`, `dcim.platform`, `dcim.interface`, `dcim.cable`, `extras.tag`, `extras.configcontext`, the probes' context by its name, `netbox_branching.branch`, the branches of the name, at the branch's first read or read again at the open or the close, or `core.objectchange`, the changelog | A list NetBox answered held other than the `count` it gave for it, or one object twice, or no object of an id it was asked for by id, so mapping it would give a blueprint of less than NetBox holds. The message gives the numbers, with the branch read or `main`. Read again; a list that is still not whole is a fault of NetBox's answer, to report with the branch and the list |
| `read.moved` | error | The branch read, by its name (`b`), or `main` | The read may hold two states, since NetBox reads no earlier time ([D-095](../../design/decisions.md#d-095)): the changelog read from, `main`'s or the branch's, holds above the latest id taken at the read's open, and at or below the one taken at its close, a row of a kind a read reads, every kind but a journal entry's, `extras.journalentry`, and the branch object's own, `netbox_branching.branch` (`bracket.UNREAD`); or its latest id at the close differs and no row of that id is among the rows listed; or it holds at the close another count of rows at or below the open's id than at the open, a row of a lower id written during the read; or, reading a branch, the branch read again at the close is not listed, is no longer `ready`, or was synced, its `last_sync` moved, since a sync adds no row to either changelog; or a request of the close under the branch's header was answered 400, as NetBox answers every request under the header of a branch deleted, syncing or merged. The message gives both ids and the kinds of the rows that count, or both counts, or both statuses or both `last_sync`s, or NetBox's words in the 400. On `main` no header is sent, and a 400 to the close is the transport's `NetBoxError`. Read again; the reader does not read again by itself |
| `platform.missing` | error | The device's name in NetBox (`n1`), or `dcim.device <id>` where it has none | The device has no platform, or its platform no manufacturer, so the reader document cannot choose its platform package. Give the device its platform, and the platform its manufacturer |
| `platform.unmatched` | error | The device's name (`n1`), or `dcim.device <id>` where it has none | The device's platform's manufacturer and name, compared exactly, letter case and spacing included, are a pair no row of the reader document holds. Add the pair's row to the document, or correct the names in NetBox |
| `device.name.renamed` | info | The device's name in NetBox (`N1`) | The device's name is no DNS-1123 label, so the blueprint names it by its label ([D-038](../../design/decisions.md#d-038)): lower-cased, each run of characters outside `[a-z0-9]` made one `-`, and `-` trimmed from both ends. A fidelity row whose source is `dcim.device.name` names both, and each link and probe names the device by the label. Rename the device in NetBox to read its name unchanged |
| `device.name.unmappable` | error | The device's name (`***`), or `dcim.device <id>` where it has none | The device has no name, or its name makes no DNS-1123 label: it holds no letter or digit, or its label is longer than 63 characters. Name the device in NetBox, or rename it |
| `device.name.duplicate` | error | Each device's name (`N1`, and `n1`) | Two or more scoped devices make one label, so the blueprint could not tell them apart: each is filed, its message naming its own device first and then the others, and a name two of them hold exactly, which NetBox takes on two sites, with each one's id (`n1 (dcim.device 4)`). Rename all but one of them in NetBox |
| `omit.cable.ends` | info | The cable, by its label, or `cable <id>` where it has none | A side of the cable has other than one termination, and a link has one a side. The cable is left out of the blueprint, a fidelity row `omitted` whose source is `dcim.cable`, and the rest of the network is read. Give each side of the cable one interface |
| `omit.cable.endpoint` | info | The cable, by its label, or `cable <id>` | An end of the cable is no `dcim.interface` (a `dcim.frontport`, say, a path through a patch panel), and a link ends on an interface. Left out, a fidelity row. Cable the two interfaces to each other |
| `omit.cable.outside_scope` | info | The cable, by its label, or `cable <id>` | An end of the cable is on no interface read of a scoped device, a device the scope does not hold, which is never read and is named by its interface's id, or on a virtual, bridge or LAG interface, which is no port. Left out, a fidelity row. Tag the far device to read the link, or cable a port |
| `omit.cable.management` | info | The cable, by its label, or `cable <id>` | An end of the cable is on an interface that is `mgmt_only`, and blueprint 1 refuses a link on one. Left out, a fidelity row. Cable a port that is not `mgmt_only` |
| `render.template.missing` | error | The device's name (`n1`), or `dcim.device <id>` where it has none | NetBox answered the device's render, under the branch's header, 400 in the words it answers a device with no configuration template, `No config template found for this device.`; NetBox's words are quoted, cut at 300 characters. A 400 in other words is `render.unavailable`. Assign a template to the device, its role or its platform |
| `render.failed` | error | The device's name, or `dcim.device <id>` | NetBox answered the device's render 500, its configuration template failing; NetBox's words, the template's error, are quoted, cut at 300 characters. Correct the template |
| `render.empty` | error | The device's name, or `dcim.device <id>` | NetBox answered the device's render 200 with no character but whitespace, which it answers a template that renders nothing: no configuration is defaulted. Correct the template |
| `render.invalid` | error | The device's name, or `dcim.device <id>` | NetBox answered the device's render 200 of a content type but `text/plain` (its parameters, a charset among them, aside), which the message names, or with no content type, so that NetBox's JSON envelope, say, is never taken as a configuration; or 200 `text/plain` with bytes that are no UTF-8 text, the message giving the offset of the first byte at fault. It quotes no byte. Correct the template, or report what NetBox answered |
| `render.unavailable` | error | The device's name, or `dcim.device <id>` | NetBox answered the device's render a status but 200, 500, 401 and 403, which the message gives, quoting no body; or 400 in other words than the no-template answer's, which the message quotes as text, cut at 300 characters. NetBox answered a render 400 under the header of a branch deleted, and a list 400 under that of a branch deleted, syncing or merged, so such a 400 is weighed at the bracket's close: where the close finds `read.moved`, that is the finding, and this rule is not filed for it. 401 and 403 are a refused token, raised as the transport's `NetBoxError`. NetBox answers 404 to a render where the token's account lacks `view` or `render_config` on `dcim.device`, though the read has just listed the device, so a missing `render_config` shows as this rule, 404, on every device: grant the reader's account both |
| `probe.context.absent` | error | The context the reader document names (`fylgja-probes`) | The reader document names a configuration context for the probes, and NetBox lists none of that name, compared exactly, on the branch read or `main`; no probe is read, and the rest of the read is judged. A context made on a branch is the branch's alone. Make the context, inactive, or correct the document's `probes` |
| `probe.context.active` | error | The context the reader document names | The context is active (`is_active`), so every device it applies to takes the probes into its rendered context, and a template could render them; no probe is read. Set it inactive |
| `omit.probe.outside_scope` | info | The probe's name (`n1-loop`), or the context's where the probe has none | An end of the probe names a device, compared exactly with the scoped devices' names in NetBox, that is no device of the scope, or one whose name makes no blueprint name, so its host could be placed nowhere. The probe is left out of the blueprint, a fidelity row `omitted` whose source is `extras.configcontext`, and the rest are read. Tag the device, or name it in the declaration as NetBox names it |
| `probes.version.unsupported` | error | The context's name | The context's data states a `probes_version` other than `1`, and the core's declaration loader (`fylgja_core.probes`) reads no other; no probe is given. Write the data in version 1's form ([`probes-1.schema.json`](../../formats/probes-1.schema.json)) |
| `probes.invalid` | error | The probe's name, at whose member the loader found the fault; the context's name where the fault is the declaration's own (data that is no mapping, a member missing or unknown) | The context's data violates the declaration's schema, which the loader holds it to after each end's device is made its blueprint name; no probe is given. The message gives the pointer and the loader's words, cut at 300 characters. Correct what they name |
| `probe.name.duplicate` | error | The later probe's name | Two probes of the data share a name, which names one probe; no probe is given. Rename one of them |
| `probe.gateway.outside` | error | The probe's name | An endpoint's gateway is outside its address's prefix; no probe is given. Correct the gateway or the address |
| `probe.address.duplicate` | error | The probe's name | An endpoint's address is another endpoint's host, of this probe or one before it by name; no probe is given. Give each endpoint a host of its own |
